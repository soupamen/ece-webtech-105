# Git branch cheatsheet

Use short-lived branches and focused pull requests. Never rewrite a branch that
other contributors are using.

## Inspect

```bash
git status
git branch -vv
git branch -a
git log --oneline --graph --decorate --all
```

## Create and publish a branch

```bash
git switch main
git pull --ff-only origin main
git switch -c feature/short-description
git push --set-upstream origin feature/short-description
```

Use `fix/short-description` for a bug fix and `docs/short-description` for
documentation-only work.

## Keep a branch current

```bash
git fetch origin
git rebase origin/main
```

Resolve conflicts, run the project checks, then continue:

```bash
git add path/to/resolved-file
git rebase --continue
```

Abort an in-progress rebase with `git rebase --abort`.

## Finish work

```bash
git add path/to/changed-file
git diff --cached
git commit -m "docs: clarify local setup"
git push
```

Open a pull request after checking `npm run lint` and `npm run build`. Keep the
description focused on what changed, why it changed, and how it was verified.

## Merge conflict basics

1. Run `git status` to identify conflicted files.
2. Remove the `<<<<<<<`, `=======`, and `>>>>>>>` markers.
3. Preserve the intended behavior from both sides where possible.
4. Run the relevant checks.
5. Stage the resolved files and continue the merge or rebase.

Use `git merge --abort` if a merge should be cancelled.

## Safe cleanup

```bash
git branch --merged
git branch -d feature/short-description
git push origin --delete feature/short-description
git fetch --prune
```

Do not use `git reset --hard`, `git clean -fd`, or force-push a shared branch
without explicit agreement from the team.
