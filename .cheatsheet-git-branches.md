# Fiche Git : les branches

## 1. Concepts clés

- **Branche** = simple pointeur mobile vers un commit. Créer une branche est quasi gratuit.
- **HEAD** = la branche (ou le commit) sur laquelle tu es actuellement.
- **origin** = nom par défaut du dépôt distant. `origin/main` = copie locale de `main` du remote.
- **Fast-forward** = merge sans nouveau commit (la branche cible n'a pas divergé).

---

## 2. Voir les branches

```bash
git branch                  # branches locales (* = branche courante)
git branch -a               # locales + distantes
git branch -r               # distantes uniquement
git branch -vv              # + dernier commit + branche suivie (upstream)
git branch --merged         # branches déjà mergées dans la courante
git branch --no-merged      # branches pas encore mergées
git status                  # branche courante + état
git log --oneline --graph --all --decorate   # graphe de toutes les branches
```

---

## 3. Créer une branche

```bash
git branch feature/login            # crée (sans basculer)
git switch feature/login            # bascule dessus
git switch -c feature/login         # crée + bascule (le plus utilisé)
git switch -c feature/login main    # crée depuis main (ou un autre commit/branche)
git switch -c fix/bug abc1234       # crée depuis un commit précis
```

Ancienne syntaxe équivalente : `git checkout -b feature/login`

**Pousser la nouvelle branche sur le remote :**

```bash
git push -u origin feature/login    # -u = lie la branche locale à la distante
```

---

## 4. Changer de branche

```bash
git switch develop1
git switch -                # revient à la branche précédente
```

> Si tu as des modifs non commitées qui gênent : `git stash` avant, `git stash pop` après.

---

## 5. Renommer une branche

```bash
git branch -m ancien-nom nouveau-nom    # depuis une autre branche
git branch -m nouveau-nom               # renomme la branche courante

# Si déjà poussée : mettre à jour le remote
git push origin -u nouveau-nom
git push origin --delete ancien-nom
```

---

## 6. Supprimer une branche

```bash
git branch -d feature/login         # locale, refuse si pas mergée (sécurisé)
git branch -D feature/login         # locale, force (perte possible de commits)
git push origin --delete feature/login   # distante
git fetch --prune                   # nettoie les références distantes supprimées
```

> Tu ne peux pas supprimer la branche sur laquelle tu es. Fais un `git switch main` avant.

---

## 7. Merge

### Cas A : intégrer `developX` dans `main`

```bash
git switch main
git pull origin main            # d'abord mettre main à jour
git merge developX              # fusionne developX dans main
git push origin main
```

### Cas B : récupérer `main` dans `developX` (rester à jour avec main)

C'est probablement le "pull main from developX" que tu cherches :

```bash
git switch developX
git fetch origin                # récupère l'état du remote
git merge origin/main           # intègre main dans developX
# ou en une commande, sans changer de branche :
git pull origin main            # (fetch + merge de origin/main dans la branche courante)
```

### Options utiles

```bash
git merge --no-ff developX      # force un commit de merge (garde l'historique de branche visible)
git merge --squash developX     # combine tous les commits en 1 seul (à commiter ensuite)
git merge --abort               # annule un merge en cours (conflits)
```

---

## 8. Résoudre un conflit

1. `git merge ...` → message `CONFLICT`
2. `git status` → liste les fichiers en conflit
3. Ouvrir les fichiers, repérer les marqueurs :
   ```
   <<<<<<< HEAD
   ton code (branche courante)
   =======
   code de l'autre branche
   >>>>>>> developX
   ```
4. Choisir/éditer, **supprimer les marqueurs**
5. ```bash
   git add fichier.java
   git commit            # finalise le merge
   ```

Raccourcis :
```bash
git checkout --ours fichier     # garder ta version
git checkout --theirs fichier   # garder l'autre version
git mergetool                   # outil graphique
```

---

## 9. Rebase (alternative au merge)

```bash
git switch developX
git rebase main             # rejoue tes commits par-dessus main (historique linéaire)
git rebase --continue       # après résolution d'un conflit
git rebase --abort          # annule
git rebase -i HEAD~3        # nettoie/réordonne/squash les 3 derniers commits
```

| | Merge | Rebase |
|---|---|---|
| Historique | Conserve la vraie histoire (commit de merge) | Linéaire, propre |
| Sûr sur branche partagée | Oui | **Non** |
| Réécrit les commits | Non | Oui |

> **Règle d'or : ne jamais rebase une branche déjà poussée et utilisée par d'autres.**

---

## 10. Pull, fetch, push

```bash
git fetch                   # télécharge sans rien modifier (sûr)
git pull                    # = fetch + merge
git pull --rebase           # = fetch + rebase (historique plus propre)
git pull origin main        # tire main dans la branche courante
git push                    # pousse la branche courante (si upstream configuré)
git push -u origin ma-branche   # 1er push + configure l'upstream
git push --force-with-lease     # force push plus sûr (après rebase)
```

Configurer l'upstream d'une branche existante :
```bash
git branch --set-upstream-to=origin/developX developX
```

---

## 11. Récupérer un commit précis : cherry-pick

```bash
git switch main
git cherry-pick abc1234         # applique ce commit sur la branche courante
git cherry-pick A..B            # une plage de commits
```

---

## 12. Comparer des branches

```bash
git diff main..developX             # différences entre les deux
git diff main...developX            # modifs de developX depuis le point commun
git log main..developX --oneline    # commits dans developX absents de main
git log developX..main --oneline    # l'inverse
git diff --stat main developX       # résumé par fichier
```

---

## 13. Stash : mettre de côté son travail

```bash
git stash                   # met de côté les modifs
git stash -u                # inclut les fichiers non suivis
git stash list
git stash pop               # réapplique + supprime
git stash apply             # réapplique + garde
git stash drop              # supprime
```

---

## 14. Annuler / récupérer

```bash
git restore fichier                 # annule modifs non stagées
git restore --staged fichier        # retire du staging
git reset --soft HEAD~1             # annule le dernier commit, garde les modifs stagées
git reset --hard HEAD~1             # annule le dernier commit ET les modifs (danger)
git revert abc1234                  # crée un commit qui annule abc1234 (sûr en équipe)
git reflog                          # historique de HEAD : sauve-vie pour retrouver un commit perdu
git switch -c rescue abc1234        # recrée une branche sur un commit retrouvé via reflog
```

> Une branche supprimée par erreur ? `git reflog` → trouver le SHA → `git switch -c nom SHA`.

---

## 15. Worktree : plusieurs branches ouvertes en même temps

```bash
git worktree add ../projet-fix fix/bug   # checkout de fix/bug dans un autre dossier
git worktree list
git worktree remove ../projet-fix
```

---

## 16. Conventions de nommage

```
feature/nom-court      # nouvelle fonctionnalité
fix/nom-du-bug         # correction de bug
hotfix/urgence         # correctif urgent en prod
refactor/xxx           # refonte
docs/xxx               # documentation
release/1.2.0          # préparation de release
```

Garder des noms en minuscules, tirets, sans espaces.

---

## 17. Workflows courants

**Feature branch (simple, recommandé pour projets de groupe) :**
```
main (stable)
  └── feature/x   → commits → Pull/Merge Request → merge dans main
```

**Git Flow (plus lourd) :** `main` + `develop` + `feature/*` + `release/*` + `hotfix/*`

### Routine quotidienne en groupe

```bash
git switch main && git pull                 # 1. se mettre à jour
git switch -c feature/ma-tache              # 2. nouvelle branche
# ... coder, git add, git commit ...
git fetch origin && git merge origin/main   # 3. se resynchroniser avant de pousser
git push -u origin feature/ma-tache         # 4. pousser
# 5. ouvrir une Pull Request, puis après merge :
git switch main && git pull
git branch -d feature/ma-tache              # 6. nettoyer
git fetch --prune
```

---

## 18. Protéger / bonnes pratiques

- Ne jamais commiter directement sur `main` (protéger la branche dans GitHub/GitLab).
- Commits petits et messages clairs (`feat: ajoute la recherche`, `fix: corrige le NPE`).
- `git pull` / `git fetch` **avant** de commencer à travailler et avant de pousser.
- Supprimer les branches mergées pour garder un dépôt propre.
- Éviter `git push --force` ; préférer `--force-with-lease`.
- Ajouter un `.gitignore` dès le début (`target/`, `*.class`, `.idea/`, etc.).

## 19. Alias pratiques (`~/.gitconfig`)

```bash
git config --global alias.st "status -sb"
git config --global alias.lg "log --oneline --graph --all --decorate"
git config --global alias.co "switch"
git config --global alias.br "branch -vv"
```

Usage : `git lg`, `git st`, ...

## 20. Mini-résumé (aide-mémoire)

| Action | Commande |
|---|---|
| Lister | `git branch -a` |
| Créer + basculer | `git switch -c nom` |
| Basculer | `git switch nom` |
| Renommer | `git branch -m nouveau` |
| Supprimer locale | `git branch -d nom` |
| Supprimer distante | `git push origin --delete nom` |
| Merge X dans courante | `git merge X` |
| Mettre à jour depuis main | `git fetch && git merge origin/main` |
| Pousser (1re fois) | `git push -u origin nom` |
| Rebase sur main | `git rebase main` |
| Annuler un merge | `git merge --abort` |
| Retrouver un commit perdu | `git reflog` |
